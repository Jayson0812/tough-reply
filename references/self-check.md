# 输出前自查

每一版都要过。有一条不合格就改，改完再输出。

## 1. 事实

- [ ] 回复里的进度、理由、数据、时间，都是用户说过的
- [ ] 没有为了让理由更充分，自己加「我在赶 XX 项目」「我今天要开会」
- [ ] 截图里认不清的地方，没有猜着写进回复

## 2. 承诺

- [ ] 没替用户答应截止时间（「今天一定给你」）
- [ ] 没替用户答应加班、周末处理
- [ ] 没替用户答应以后的事（「下次一定帮你」）
- [ ] 没替用户答应费用、折扣、额外交付
- [ ] 给方案版里出现的承诺，都列进了「发之前确认」

## 3. 关系

- [ ] 对上级：没有撒娇、没有命令口气、结论在前
- [ ] 对平级：不卑微、不说教
- [ ] 对下属：清楚、不阴阳
- [ ] 对客户：礼貌、不承诺范围外的事
- [ ] 背景卡里的「底线」一条都没越过

## 4. 语气和 AI 腔

- [ ] 过了一遍 `anti-ai-voice.md` 的「一定要删的」
- [ ] 回复正文里没有任何写给用户看的话
- [ ] 三版之间有真正的区别，不是换了几个词

## 5. 安全

- [ ] 没有骂人、人身攻击、歧视性内容
- [ ] 涉及骚扰、违法要求、劳动权益时，按 `when-not-to-text.md` 处理了
- [ ] 回击版不会让用户在公司里陷入更大的麻烦；有风险的在 ✅ 里说明

## 「发之前确认」写什么

只写用户真的需要核对的，三条以内最好：

- 你的假设：「我假设你明天上午有空，没有的话删掉第二句」
- 回复里的承诺：「③ 里答应了周四交，确认来得及再发」
- 可能的后果：「④ 发出去后对方可能会说你较真，想好要不要接」
- 隐私提醒（同一次对话只提醒一次）
