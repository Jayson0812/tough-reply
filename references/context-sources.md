# 自动拉上下文

背景卡记的是不常变的东西：关系、说话风格、底线。每次都在变的事实，比如进度、约定、日程，最好不要靠用户现说，而是让 AI 自己去翻记录。理由来自真实记录，回复才站得住。

## 什么时候能用

你所在的工具接上了用户的办公数据：办公 IM、邮件、日程、会议纪要、待办、项目协同工具（通过连接器、MCP、命令行工具等方式）。

没接上就跳过这一步，按 `SKILL.md` 第 3 步直接问用户，或者请用户贴几条相关聊天。

## 翻什么

只翻和这条消息有关的，按场景挑：

| 来源 | 找什么 | 哪些场景最有用 |
|---|---|---|
| 和对方的聊天记录 | 这件事之前怎么约定的；对方平时怎么说话 | 所有场景；读懂对方时尤其有用 |
| 项目协同工具、待办 | 任务状态、负责人、截止时间、谁改过什么 | 催进度、被甩锅、临时加活、领导问进展 |
| 日程 | 今明两天忙不忙，什么时候有空 | 拒绝被甩活、临时加活、下班消息（给时间点时有依据） |
| 会议纪要 | 分工、约定、决策 | 被甩锅（摆事实）、客户追问、群里被点名 |
| 邮件 | 对外承诺过什么、客户原话 | 客户甲方、被甩锅 |

一般看最近 7～14 天。这件事有明确的开始时间，就从那天看起。

## 规矩

- **只读**：不发消息，不改任务状态，不回邮件，不建日程。
- **少翻**：只翻和这条消息、这个人、这件事相关的内容，不去浏览无关的聊天和私人信息。
- **说清楚读了什么**：在输出最前面的 🔍 一行写明，比如「我看了你和产品 A 最近 7 天的聊天，以及任务单上这个需求的状态」。
- **拉到的事实也要确认**：写进回复的进度、约定、时间，在 ✅ 里列出来请用户核对。记录可能过时，用户的话优先。
- **找不到就说找不到**：不要因为没翻到记录，就补一个看起来合理的说法。
- **被甩锅时**：找到能证明分工的记录（纪要、任务单、聊天），在 ✅ 里告诉用户在哪里，方便用户转发或截图。

## 和背景卡的关系

- 先读背景卡，再拉上下文，最后还缺什么才问用户。
- 拉上下文时发现背景卡过时了（比如对方换了岗位），问用户要不要更新卡片。
